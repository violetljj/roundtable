## 已实现：执行交接（第二批）

目标：讨论 → 执行 → 复核，用户不用再复制粘贴、重新交代任务。

用户确认推进后，以下流程已实现：

1. **任务卡**：从定稿/总结生成可编辑的任务卡——要完成什么、采用哪个方案、约束（取自约束卡）、未解决的分歧、相关文件、验收方法。用户编辑确认后才交接。
2. **隔离执行**：项目必须是 git 仓库；执行方在新建的 git worktree（新分支）里工作，不直接动用户的工作目录。
3. **执行方**：用户选择 Claude 或 Codex，界面显示两边额度。执行会话由讨论室管理（Codex 执行对话可以在桌面端打开查看）。
4. **交叉复核**：执行完把 diff 交给另一方复核，复核意见回到讨论室。
5. **用户确认合并**：用户看过 diff 和复核后，点确认才合并到原分支；也可以放弃。

权限、时限、失败后保留现场及清理规则见 ARCHITECTURE 的「执行交接」。Claude 没有采用原设想的 acceptEdits，而是宿主校验后的文本落盘；两种执行方均已在临时 Git 仓库真实走完修改、另一方审查和确认合并，小文件验收不能代表复杂项目成功率。

## 之后

本批已补关键反驳定位、双版结论、外部 skill/CLI 入口、小实验回流、论文审稿与双人讲课模式。先用这些功能观察观点歪曲、重复讨论和上下文搬运是否减少；未引入每轮强制唱反调或模型总分。

- 从当前完整轮次讨论分叉；任意历史切点需另行处理，现有会话复制不等于历史回溯。
- 本场时长上限（目前只有发言次数上限）。
- 无人值守的自动收尾另行设计；现有发言上限仍会暂停，不能等同于夜间自动定稿。手机网络访问、跨项目检索、评分、协作说明和时间线回放不在本批范围。
- 真实读取证据与历史引用版本追踪（现有主张出处和当前预览不代表已经做到）。

## 已知未验证 / 遗留

- urgent 两阶段、Codex steer 成功/失败/迟到、finish 两阶段及回执竞争现已有直接模拟测试；真实浏览器中的模型纠正和中途 finish 本次没有重跑，不能用模拟测试冒充真实验收。
- Claude 执行只支持文本新增/覆盖；删除、二进制、命令验证尚未支持。交接尚未验收复杂项目、长任务、Windows 强杀宿主后的全部子进程回收。
- 当前发言上限在下一步调度前检查：讨论阶段主动提问同样受限，并行独立提案可能超过设定次数。后续若要改成严格调用预算，需要另行设计，不能直接沿用当前计数。
- 带入很长的旧对话（几 MB）时的额度消耗和上下文压缩情况没测过。
- Codex 模型覆盖 `turn/start` 的 `model` 字段对 fork 出来的对话是否完全生效，只在少量场景实测过。
