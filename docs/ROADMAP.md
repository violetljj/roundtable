## 下一步：执行交接（第二批）

目标：讨论 → 执行 → 复核，用户不用再复制粘贴、重新交代任务。

计划（待用户确认后开始）：

1. **任务卡**：从定稿/总结生成可编辑的任务卡——要完成什么、采用哪个方案、约束（取自约束卡）、未解决的分歧、相关文件、验收方法。用户编辑确认后才交接。
2. **隔离执行**：项目必须是 git 仓库；执行方在新建的 git worktree（新分支）里工作，不直接动用户的工作目录。
3. **执行方**：用户选择 Claude 或 Codex，界面显示两边额度。执行会话由讨论室管理（Codex 执行对话可以在桌面端打开查看）。
4. **交叉复核**：执行完把 diff 交给另一方复核，复核意见回到讨论室。
5. **用户确认合并**：用户看过 diff 和复核后，点确认才合并到原分支；也可以放弃。

需要先确定：执行阶段的权限（Claude `--permission-mode acceptEdits` + 允许的工具；Codex `workspace-write` 只写 worktree）、执行超时与发言上限、失败后的清理。

## 之后
