# 圆桌讨论室：Claude × Codex

在一个网页里让 Claude 和 Codex 一起讨论问题，你在旁边实时看，随时插话。

## 启动

双击 **`启动讨论室.cmd`**，浏览器会自动打开 http://127.0.0.1:4545 。关掉那个黑色窗口就停止服务。

讨论室只会运行一份：已经开着时再双击，只会打开已有的页面，窗口随即关闭。4545 被别的程序占用时会顺延到 4546 等端口，圆桌技能和命令行入口会自动找到实际端口。

需要：Claude Code 命令行已登录（`claude auth status` 显示 loggedIn），Codex 已登录。

## 一场讨论怎么进行

1. **独立提案**：两边同时作答，互相看不到对方的内容，避免先说的一方把另一方带偏。
2. **交叉讨论**：轮流回应对方，可以互相 @ 提问；有实质分歧会保留，不强行统一。
3. **总结 + 复核**：最后没发言的一方写「三句话版 + 完整版」，另一方同时检查两版是否准确。短版说明建议、依据与证据边界、什么条件会改变建议；完整版保留共识、分歧、验证与下一步。
4. **定稿（仅在复核提出更正时）**：由当前额度更宽裕的一方把更正合并进总结，只改被指出的地方。复核无异议就不多调用模型。之前结束的讨论可以在复核下方点「合并成定稿」补一份。
5. 结束后还可以继续自由提问。

两边都认为"可以收敛"、或者到达轮数上限，且没有待送达的用户消息或约束卡更新时，就进入总结。探索想法模式不提前收敛。

讨论室规则里要求：反驳先点明回应的是哪句话，找出当前方案最脆弱的假设，不为反对而反对；事实分歧可申请小实验，偏好取舍交给你。这些规则只在开场说明一次（同时作为系统提示保留），不在每轮重复，免得模型把注意力花在守格式上。它们是提示要求，并非自动证明讨论质量。

在「结论」页查看并复制最新已完成复核/更正的三句话版和完整结论。复核意见可展开查看，复制完整结论时也一并保留。旧讨论没有短版时保留完整结论；尚未完成复核时显示原因，不开放复制。讨论结束后再发消息是**自由问答**：双方会回答，但不会改动结论。想让结论跟上，用状态条上的两个按钮：「再讨论一轮」回到交叉讨论，双方各再发言一次后重新总结、复核；「更新结论」不再讨论，直接把结束后的问答纳入，重新总结、复核。结论之后有新的问答时，状态条和结论页都会提示"尚未纳入结论"，「更新结论」变成主按钮。

讨论结束后，输入框上方的状态条会出现「查看结论」，总结类消息下的「查看结论 →」也通向同一结果页。

## 界面怎么用

- **新建**：填写问题，选择讨论方式和项目即可开始。默认使用 **Opus 5.5 · high** 和 **Astra · high**，也可在「讨论设置」更换；命令行创建时未指定模型也使用这组默认值。「补充上下文」收纳约束与已有对话，「讨论设置」收纳模型、轮数、发言上限与主张标注。新建窗口立即打开，可选模型在后台读取。
- **讨论**：顶部只放标题、模式、进度和「讨论 / 结论」切换。输入框正上方是状态条：谁在发言、为什么暂停、是否等你回答，以及当下能用的操作（打断、暂停、继续、整理结论、查看结论）；需要你处理时状态条会变成醒目的提示色。双方的独立提案并排显示，过长的一方先折叠，点「展开全文」看完整内容。「⋯」里有加轮、导出和停止。
- **结论**：独立阅读区显示短版与完整依据，复制后可带回其他工作流；点「回到讨论继续追问」恢复输入区。
- **本场设置**：右侧抽屉，直接显示约束卡内容、两边当前模型、已发言次数，下面是主张核查、小实验和执行交接。约束卡、模型、用量与上限都在抽屉里原地展开编辑，不再弹第二层窗口；小实验、执行交接和主张详情是完整的工作面板，打开时抽屉先收起。实验/执行有待处理进展时入口会显示提示。
- **侧栏底部**：只有两行——「通知」开关（绿点表示已开启，说明在悬停提示里）和「额度」概览（两边各自用得最多的额度窗口百分比），点开「额度」看账号和全部额度明细。

复核判断与结果接口使用同一套规则：“无异议，没有遗漏”等明确确认不会额外生成定稿；引用里的复核标记不算复核者自己的结论。若措辞含混，讨论停在复核阶段并提示原因，点「继续」重新复核后再交付。

## 五种讨论模式

| 模式 | 适合 | 特点 |
|---|---|---|
| 做决定 | 在几个方案里选一个 | 说清代价和选择条件，双方都认为充分时提前收敛 |
| 探索想法 | 头脑风暴 | 各自提 2–3 个不同思路、交叉组合；不提前收敛，讨论到设定轮数；总结是"想法清单" |
| 方案审查 | 审你已有的方案 | 按严重程度找问题和反例，也列出站得住的部分 |
| 论文审稿 | 投稿前检查论文 | 双方先独立审稿，再核对原文依据，生成作者回应、修改和补证据清单；不预测录用 |
| 双人讲课 | 学习陌生主题 | 先发言方讲解，另一方追问推导、反例与边界；最后附理解检验，不把沉默当作理解 |

## 从当前对话发起圆桌

安装 `roundtable` 技能后，可在支持技能的 Codex 或 Claude Code 新会话中说「把这个方案拿去圆桌讨论」或「请另一方快速审查」。技能整理问题、材料、约束后发起讨论，并在当前对话取回已复核结果。默认快速审查为 1 轮，完整讨论为 3 轮；也可明确模型与上限。

先启动讨论室。命令行同样可用：

```powershell
node scripts/roundtable.js start --input E:\path\question.json --wait --timeout 60
node scripts/roundtable.js result --id <讨论ID>
node scripts/roundtable.js wait --id <讨论ID> --timeout 60
```

JSON 使用 `topic`、项目绝对路径 `cwd`、`background`，可选 `mode`、`maxRounds`、`maxTurns`、`models`。材料不会自动继承自当前对话，具体格式见 [圆桌技能](skills/roundtable/SKILL.md)。默认地址为 `http://127.0.0.1:4545`，端口变化时加 `--url`。返回链接可直接打开对应讨论。

客户端等待到时会保留 ID；再次获取结果用同一个 ID，不重复新建。等用户回答、暂停或失败会明确返回状态。关闭当前对话后不会自动把结果推送回来。其他机器可把 `skills/roundtable` 复制到客户端技能目录，并按实际位置调整仓库路径；无需额外 npm 依赖或 MCP 配置。

## 用小实验裁决

进入交叉讨论后，在完整模型发言旁点「据此起草小实验」，或先选中正文再点「据选文起草小实验」。明确标出实验判据与步骤的发言会显示「查看实验建议」，把这些字段带入可编辑草稿；未明确给出的内容留空，不额外调用模型猜测。也可以从「本场设置」进入「小实验」。写明**分歧、什么结果会改变结论、实验步骤**和 1–30 分钟时限。起草和保存不调用模型；保存后讨论暂停，当前发言结束后才能点「批准这张实验卡并开始」，这时才开始消耗执行模型额度。回传后的讨论也会消耗额度；运行时限不是额度上限。

- 项目需要干净且有提交的 Git 起点。实验从该 HEAD 建立临时副本，不包含未提交和忽略文件；暂不支持子模块。
- 双方都可提出实验，实际执行目前由独立的 Codex 工作区写入沙盒完成，禁止网络。允许在副本中产生测试文件；原讨论会话仍只读，实验不提交、不合并、不推送。
- 运行中可取消，达到时限或失败不会自动延长、重跑。结果保存批准卡、来源 HEAD、报告与错误；报告包含模型解释，生成完整报告不等于判据通过。
- 点「带回讨论并继续」才把报告作为证据发给双方重新判断；结束后的讨论会重新进入交叉讨论并产生新总结。仍遵守原发言上限，必要时由你调整。
- 回传附带的固定请求会标明「讨论室自动请求，由你带回实验触发」，不会显示成你的原话；导出记录与发给模型的提示也保留这一来源。旧版实验回传记录同样可识别。
- 干净的成功实验副本自动清理；有产物、失败或取消时保留路径供检查。以前的实验仍可展开查看，服务重启不会偷偷重跑。
- 从发言起草的实验会保留原发言关联和摘录，状态、报告入口以及双方回传后的重新判断挂回原文。旧实验可从原文直接定位到历史记录，查看历史时收起当前实验的批准按钮，避免误操作。

## 约束与事实卡

新建时填的"约束与事实卡"会固定附在双方**每一次**发言的开头，与旧对话、记忆冲突时以它为准。
讨论中在「本场设置」里点约束卡旁的「编辑」随时修改：版本号 +1，双方下一次发言会同时收到新旧两版，明确旧版本作废。卡片更新没送达双方之前，讨论不会提前收敛。

## 双边行为卡（试用）

给某个型号写一句可能的倾向提醒，分**长处**和**短处**两类，用来扬长避短。双方看到同样的卡，但另一方的做法不同：

- **长处卡**（如 Claude「设计给到具体方案」、Codex「点出真实的失败路径」）：本人遇到这类问题时主动多承担；对方遇到这类问题时先请它出方案、重点参考它的意见，同时保留自己的判断。
- **短处卡**（如 Codex「保护设计是否必要」、Claude「发散之后落到可执行方向」）：本人出现这种情况时照做；对方看到确实出现时直接指出（引用原话、说明怎么改），本人被指出后先核对原话，属实就承认改正，不另找理由辩护。

默认带上一长一短各一对。

卡片只是提醒，不是给模型下定论。发给模型的说明里写明：这些是你凭经验写的可能倾向，不代表一定存在；是否出现看本场实际发言，不要据此给对方贴标签，也不要为了显得没有而矫枉过正。

怎么用：

- **开关**：「本场设置 → 双边行为卡」右上角的开关；新建讨论时在「讨论设置」里勾选。顶部出现「行为卡 · N」表示 N 张正在生效，点它直接跳到设置。
- **增删改**：每张卡一行，标着提醒谁、长处还是短处，勾选即生效；点「调整」修改名称、提醒谁、长处/短处、一句提醒和适用型号，删除也在这里。「＋ 添加」可以从预设里挑，也可以自己写空白卡。
- **继承**：最近一次修改（包括开关）会成为之后新讨论的默认卡片，直到下次修改；每场讨论各存一份，改新的不影响旧的。
- **型号**：按完整型号 ID 匹配，编辑时点型号标签就能加上或去掉。Claude 的别名（opus、fable、命令行默认）按命令行实际报告的型号匹配；不匹配的卡会注明"不适用当前型号"。

改动从双方下一次发言起生效，当前发言沿用原卡；停用会明确通知旧卡作废。采用卡片的发言旁显示当次版本，悬停可看当时的内容，供后续有卡/无卡对照。初始规则来自你的经验，尚未验证效果；误伤必要保护或出现编造理由时，调整或停用对应的卡。

## 引导下一轮

输入框下方的「引导下一轮」可以预填一句只针对下一轮的话：展开探索、回到可执行方案、检查必要性。它只是帮你起个头，改完再发；不会写进行为卡或长期设置。

## 重命名

讨论标题默认是你的完整问题。双击标题（或「⋯ → 重命名」）可以改成好认的短名，只影响侧栏和标题显示；双方讨论的始终是原始议题，悬停标题可以看到原文。清空就恢复原样。

## 你能做什么

| 操作 | 效果 |
|---|---|
| 直接发消息 | 排在当前发言之后，下一位先回应你 |
| @Claude / @Codex | 指定下一位回答者；如果恰好轮到它，仍计入当前轮次，否则插队回答不占轮次 |
| 勾选「立即纠正」 | Claude 会被打断、按你的话重来；Codex 不打断，你的话直接插进它正在进行的思考 |
| ⏸ 暂停 | 当前发言说完后不再继续 |
| ✋ 打断 | 立即停止当前发言，没说完的内容不会转给对方 |
| 再加一轮 / 整理结论 / 停止 | 加轮数 / 叫停并总结 / 立即停止不总结；整理结论在状态条上，加轮和停止在「⋯」里 |
| 「本场设置」里的模型行 | 随时切换两边的模型和推理强度，下一次发言生效 |
| 「本场设置」里的「已发言」行 | 查看本场每一方的发言次数、token 用量、耗时；调整发言上限和轮数 |

你的每条插话下面会显示送达状态：**等待送达 → 已送达 → 已回应**。"已回应"指对方在一次完整发言里收到了它，不代表一定照做。

本场发言达到上限时，独立提案和交叉讨论会暂停（默认 20 次），这两个阶段的插话和 @提问也受限制。总结、复核、定稿和讨论结束后的自由问答不受限制。已开始的发言不会因达到上限而中断，双方并行提案可能超过设定次数。

## 主张、出处与定向核查

新建讨论时勾选「要求标注可核查主张」，双方才会把关键判断写成 `【主张】`、`【来源】`、`【验证】`；默认不勾选，因为格式要求会分散模型的注意力，需要逐条核实时再开。「本场设置」里的「主张与核查」汇集这些标记。点击一条查看原发言、出处和验证方法；你可以分别标记「双方共识 / 存在分歧」与「待核实 / 有支持 / 有反证」，并保存备注。两种状态彼此独立，均是你的标记，不会自动改变模型观点；没有出处的推测仍保留。

来源由发言方提供，「本场读取」是作者自述。点击项目内 `文件:行号` 可预览当前 UTF-8 文本和内容哈希；当前文件可能已与发言时不同，预览不代表模型确实读过或主张已被验证。项目外、链接、部分本机配置与私密文件不提供预览。

在主张详情点「请另一方核查」，或在任意完整模型发言旁点常驻的「请对方核查」，会创建可追溯的定向用户消息，请对方检查来源、寻找反证并给出验证方法。沿用当前讨论调度与发言上限，会触发模型发言并消耗额度；独立提案阶段禁用，避免提前泄露观点。旧讨论无需迁移，有标记的发言自动出现在清单；没开启标注或没有标记，也能核查整条发言。

原发言旁会显示核查待回复或关联回复数，点开可跳到具体请求与回复；回复也能回到原文。你可以给整条发言标记「有依据／需修正／仍不确定」，保存理由与出处，界面明确注明是你的判断。另一个模型同意不会自动变成事实认证。失败或被打断的半截发言不算核查回复；旧记录未保存明确回复关联时只保留请求入口，不根据时间相邻猜测结果。

## 桌面通知

侧栏点击「通知」并允许浏览器权限后，当前打开的讨论需要你回答、完成、发言失败或达到上限时会通知。点击通知返回对应讨论；手动暂停、停止、历史记录和重连快照不补发通知。只在页面保持打开时工作，不监控其他未打开的讨论；系统显示仍受浏览器权限和 Windows 通知设置影响。

## 项目、记忆和桌面端

- **按项目分组**：左侧讨论列表按项目文件夹分组，分组上的「＋」可以直接在该项目里新建讨论。
- **项目上下文自动带入**：选了项目后，Claude 会读 `CLAUDE.md` 和它对这个项目的记忆，Codex 会读 `AGENTS.md` 和它的记忆。新建表单里会显示带入了哪些。
- **带入已有对话**：可以选择 Claude 桌面端（Code 标签页）或 Codex 桌面端里已有的一次对话。讨论室用的是它的**副本**：会记得那次对话的内容，桌面端的原对话不受影响。
- **回到桌面端**：讨论室的 Codex 对话会出现在 Codex 桌面端，名字是「圆桌：话题」。如果你在桌面端打开着它，讨论室会自动复制一份接着用，历史完整保留。在「结论」页复制最新已复核的完整结论，可以粘贴到任一桌面端继续推进。

## 从结论交给执行方

讨论结束后在「本场设置」中点「交给 AI 执行」，任务卡会带入结论、复核意见和约束卡。补充相关文件与验收标准，可以编辑后选择 Claude 或 Codex，再点「确认并开始执行」。

- 项目必须是有提交的 Git 仓库，启动时工作区要干净。交接从当前已提交版本建立独立 worktree 和新分支，原项目保留原状。
- Codex 在该工作区的写入沙盒内实现并验证；Claude 生成文件变更，由程序校验路径后落盘，不能自行运行命令或测试。验收报告会保留这一区别。
- 执行后保存一个提交，再由另一方只读检查完整 diff。界面展示执行报告、差异和复核意见；「待确认合并」只表示复核已完成，不代表没有问题。
- 用户检查后确认合并；程序只在原分支、原起点仍一致且工作区干净时快进合并，不自动推送。原项目已变化时保留结果，交给用户手动整合。
- 每次交接调用执行方与复核方各一次，默认总时限 15 分钟，可设 1–60 分钟；这限制的是发言次数和运行时间，不是 token 账单。可中途取消，服务重启后不会自动续跑。
- 放弃或合并后清理干净的任务工作区，保留分支与报告；未提交改动、忽略文件或清理失败时保留现场并显示路径。暂不支持含子模块的项目。

## 安全

讨论期间两边都**不改项目文件**。在「本场设置 → 讨论能力」可以放开以下能力，所有讨论共用，默认全开，下一次发言生效：
- **联网查资料**：双方可网页搜索；Claude 还能读网页、用 exa，Codex 也接上 exa。Codex 的 exa 需要你自己设用户环境变量 `EXA_API_KEY`（`setx EXA_API_KEY <key>`，不用重新登录），没有时会被免费额度限流；插件全开时 Codex 另有 Exa 应用可用。
- **Claude 跑只读命令**：只放行 `git log/show/diff/status/blame`、`ls`、`cat`、`head`、`tail`、`wc` 等；写文件、重定向、管道、`--output` 一律自动拒绝。需要 Git Bash。
- **Claude 读 Claude Docs**：只能读取和检索，创建、编辑、删除会被拒绝。
- **Codex 插件全开**：浏览器、文档、Slack、日历、电脑操控等插件都会加载。Codex 只能整体开关插件；它不弹窗确认，插件的对外操作（发消息、建日程、网页提交）发出去撤不回。项目文件仍是只读沙盒。

全部关掉时与原来一样：Claude 只有 Read / Grep / Glob、不加载 MCP；Codex 只读沙盒、禁止联网、插件全关。Claude 的限制靠白名单权限模式保证，没列入的工具和命令自动拒绝，不靠提示词。执行和小实验不受这些设置影响。

服务只监听本机 127.0.0.1，校验 Host 头，POST 请求要求 JSON。交接、主张标注与定向核查写入接口另检查网页同源；其他接口没有单独校验 Origin，也没有账号鉴权；这些限制不等于完整的访问控制。
